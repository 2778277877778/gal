## 1. 时间结构

一学年只算在校的 8 个月：**9、10、11、12、3、4、5、6 月**，一个月一回合。寒假、暑假不进回合，用一段过场带过（沿用现在「寒假蒙太奇」的写法）。三年 24 回合。

| 学年 | 回合 | 月份 | 每回合 AP | 学年末考试 |
|---|---|---|---|---|
| 高一 | T1–T8 | 9–12、3–6 | 3（T8 为 2） | T8 线 70 |
| 高二 | T9–T16 | 同上 | 3 | T16 线 75 |
| 高三 | T17–T24 | 同上 | 3（T20、T24 为 2） | T24 毕业线 80 |

- 回合内还是五段：月初 → 自由行动（AP）→ 固定事件 → 结算 → 存档。
- 考试沿用现在的掷点：成绩 = 学习 + 随机(−5, +5)，只有及格线随学年抬。
- 高三的校历压缩：一模在 T17，艺考/体考在 T20，二模在 T22，志愿在 T23，高考在 T24。

## 3. 特殊事件：随机、点缀、不推主线

这是这一版的重点。规则写死，防止随机事件把主线搅乱。

1. **每月掷一次**，月初 `start_month()` 之后执行：距离上次特殊事件 ≥ 1 回合、且掷中概率 **55%**，就触发一个。期望约 1.8 回合一次，即「大约每两个月一个」。
2. **同年不重复**：一个学年内同一事件不抽第二次；相邻学年可以重复，但换场景或换角色。
3. **不推主线**：特殊事件**不置任何 TRUE Flag、不动学习/压力/金钱、不改主线 Flag**，只给场景、台词和一次小选择（小选择只记字符串变量）。
4. **三个女主轮流出场**：事件自带 `cast`（1–3 人）。抽到谁按权重：
   `w(角色) = 1 + bond(角色)`（bond 见 §6）。同一事件连续两次抽到同一个人，第三次强制换人。
5. **固定事件优先**：某回合的固定骨架事件（考试、艺考、分班、毕业等）先播；两者都触发时，特殊事件挪到该回合自由行动段的开头，当作「这个月还发生了件事」。
6. **男主和三个女主的对话参杂**：多人群像事件（食堂、大扫除、元旦）里，三人都在场，台词交替；单人事件只有一个人。

|---|---|---|---|---|

## 5. 结局：三条线各一个 TRUE + 一个 END

**定了，按这个做**（要改只是一句话的事，但先让写程序的人有准）。

| 结局 | 对象 | 门槛（全部满足） |
|---|---|---|
| TRUE「最后一个音」 | 周墨 | 学习 ≥ 75、压力 ≤ 70、六个周墨线 Flag 齐、`bond(zhoumo)` ≥ 7、T23 志愿选音乐 |
| TRUE「跑完」 | 夏幸悠 | **体力 ≥ 60**、压力 ≤ 70、`xiayou_injury`（Flag）、`seen` 含 `quit_sport`、`bond(xiayou)` ≥ 7、T23 选择陪她走体育 |
| TRUE「允许出错」 | 第三位 | **学习 ≥ 80**、压力 ≤ 70、`h3_fall`（Flag）、`seen` 含 `quit_first`、`bond(heroine3)` ≥ 7、T23 选择支持她换方向 |
| END「琴盖没开」 | — | 以上都不满足 |

三条线各自守一个数值门槛（周墨看学习、夏幸悠看体力、第三位看学习更狠一档），压力是共用的。**`bond` 只决定「和谁」，升到 7 是必要条件，不是唯一条件**——这样玩家不会觉得结局是随机抽的，也不会因为搞不懂隐藏数值就翻车。

- 判定顺序：先看学习/压力这类硬门槛 → 再看该线 Flag → 最后看 `bond` 和 T23 选择。任何一条不满足就掉到 END。
- 三条线共用同一个 END，正文仍按 `end_variant()` 的 A/B/C 取；A/B 是对周墨线说的，夏幸悠线和第三位线的 END 各加一段自己的收尾（不另开结局）。
- `route` 变量只记最后走的是哪条线，纯展示用，不参与判定。

## 6. 变量：每个女主一套（给后端）

原则：**扁平命名**，一个变量只属于一个角色，拼提示词时直接取名字就够，不用翻嵌套结构。

### 6.1 全局

| 变量 | 类型 | 说明 |
|---|---|---|
| `year` | int | 1–3 |
| `turn` | int | 1–24，现有 `turn` 扩到 24 |
| `route` | str | `none` / `zhoumo` / `xiayou` / `heroine3`，T23 之后才可能非 `none`，只做展示 |
| `save_seed` | int | 建新档时生成一次的 32 位随机数，跟着存档走；AI 生成的稳定性靠它（§7.3） |
| `study` `stress` `stamina` `money` `ap` | int | 沿用 `stats.rpy` |

### 6.2 每个女主 4 个

以周墨为例，另两位把前缀换掉即可：

| 变量 | 类型 | 范围 | 谁改 | 说明 |
|---|---|---|---|---|
| `zhoumo_bond` | int | 0–10 | `add_bond("zhoumo", n)` | 关系值，**界面上不显示数字** |
| `zhoumo_mood` | str | 见下 | `set_mood("zhoumo", mood)` | 她当前的状态，由事件写 |
| `zhoumo_seen` | list[str] | — | `know_secret("zhoumo", tag)` | 她愿意让你知道的事 |
| `zhoumo_talks` | int | 0+ | `add_talk("zhoumo")` | 累计互动次数，给随机事件抽人用 |

`mood` 只留四个值，够用又好写提示词：`calm`（平静）、`tense`（绷着）、`low`（低落）、`warm`（放松）。

`seen` 的 tag 举例：周墨 `piano_secret` / `family_pressure` / `stop_at_13`；夏幸悠 `grade_shame` / `injury` / `sport_dream`；第三位 `first_lose` / `parents_pressure` / `quit_first`。

### 6.3 主线 Flag 扩容（13 → 16）

三年版要加三个主线 Flag，都是固定事件触发，不随机：

| Flag | 触发 | 用途 |
|---|---|---|
| `xiayou_injury` | T14 夏幸悠受伤 | 她这条线的转折 |
| `h3_fall` | T15 第三位掉出前三 | 她这条线的转折 |
| `audition` | T20 艺考 / 体考 | 高三线摊牌 |

`stats.rpy` 的 `FLAG_NAMES` 从 13 个扩到 16 个，`TRUE_FLAGS`（周墨线六项）不动。

### 6.4 规矩

1. **关系变量不进主线判定**：TRUE 只看学习、压力、主线 Flag。`bond` 只影响随机事件出谁、台词变体、结局对象。
2. **一个变量只有一个入口**：`bond` 走 `add_bond`，`mood` 走 `set_mood`，`seen` 走 `know_secret`，别在剧情里直接 `$ zhoumo_bond += 1`（跟 `$ study += 5` 一个道理）。
3. **代码位置**：新建 `game/systems/characters.rpy`，放三个角色的初始值、四个入口函数、`cast_weight(id)`（= `1 + bond`）。`stats.rpy` 不塞角色数据。
4. **提示词拼法**：每回合结算时把三个角色序列化成
   `{"zhoumo": {"bond": 6, "mood": "low", "seen": ["piano_secret"], "talks": 12}, ...}`
   直接塞进生成用的上下文，不用再从别处凑。
5. **主角名还是 `XXX`**：变量、提示词模板里不写主角名。

## 7. 对话由 AI 生成，走向由主线锁定

一句话：**句子散，骨架不散。** 每个玩家读到的每一句都可能不同，但 beat 顺序、出场人、Flag、选项、结局永远相同。

### 7.0 变与不变

| 档 | 内容 | 谁定 |
|---|---|---|
| **可以变** | 每句话怎么说、语气、打岔、闲聊、对同一件事的复述角度 | AI 生成 |
| **不能变** | beat 顺序、谁出场、置哪个 Flag、给哪些选项、选项跳哪、结局判定 | 剧本 |
| **必须一致** | 秘密只在 `seen` 里有了之后才能说、称呼固定、回指前文不打架、**同一存档读档重看结果不改** | 校验 + seed（§7.3） |

| 东西 | 谁决定 | 存在哪 |
|---|---|---|
| 这个月放哪几段、什么顺序 | 剧本 | `.rpy` 的 label |
| 每段必须发生什么、置哪个 Flag、动哪条数值 | 剧本 | beat 表 |
| 选项有哪几个、选完跳哪 | 剧本 | `menu` |
| 结局判定 | 剧本 | `true_ending()` / `end_variant()` |
| **这段里每句话怎么说** | **AI 生成** | 运行时 |
| 生成失败怎么办 | 剧本兜底台词 | beat 表的 `fallback` |

### 7.1 beat 契约

每段固定事件有一个稳定的 `beat_id`（`t3_night_comfort`、`t9_newclass_seat`），写进剧本就**永远不改名**。AI 只拿到这个 id 和它周围的信息，拿不到"下一段是什么"。

**输入**（后端拼一个 JSON）

```
{
  "beat_id": "t3_night_comfort",
  "seed": 1948573312,
  "scene": "piano_room_night",
  "speakers": ["zhoumo"],
  "goal": "她按着卡住的键，主角安慰她，她说出停琴的事",
  "choice": "key",
  "state": {
    "zhoumo":   {"bond": 6, "mood": "low",   "seen": ["piano_secret"], "talks": 12},
    "xiayou":   {"bond": 3, "mood": "calm",  "seen": [],                "talks": 5},
    "heroine3": {"bond": 2, "mood": "tense", "seen": [],                "talks": 4}
  },
  "prev": ["上一段最后的两三句台词"]
}
```

**输出**：只有台词，没有别的

```
[{"speaker": "zhoumo", "line": "……"}, {"speaker": "XXX", "line": "……"}]
```

旁白、选项、Flag、数值、跳转一律不产，全部由剧本给。

### 7.2 硬约束（写进系统提示词，也当场校验）

1. 只能说 `speakers` 里的人的话，不许新增角色，不许让不在场的人开口。
2. 不许说出 `seen` 里没有的秘密：`seen` 没有 `piano_secret` 时，一句都不许提"你会弹琴"。
3. 不许替玩家做选择，不许写玩家的心理活动。
4. 主角嘴笨：单句 ≤ 24 字，说不利索，不说漂亮话——这是人设，不是风格建议。
5. 一段总长 ≤ 6 句、≤ 160 字，超了截断，不重试。
6. 称呼固定，不许改名、不许换称呼。
7. 生成结果**不写回** `bond` / `mood` / Flag：AI 只产文本，状态只由剧本改。

### 7.3 兜底与缓存

### 7.3 存档级 seed（「每个玩家不一样」靠它）

只靠状态不够：同一份状态、同一次读档，如果重新生成，玩家会看到两版对不上的台词。所以 seed 必须进存档。

- `save_seed`：**新建存档时生成一次**的 32 位随机整数，写进存档状态，跟着存档走；读档不变。
- 每段生成用自己的 `gen_seed`：`gen_seed = hash(save_seed, beat_id, choice)`，用固定算法的字符串哈希（别用会变的 `random` 全局种子）。
- 效果：**同一个存档、同一个 beat、同一个选择 → 永远同一段文字；不同存档 → 不同文字**。这就是「形散」的来源，也是读档不穿帮的保证。
- 生成请求把 `seed` 当参数传给模型（temperature 固定，别每次随机），服务端不认 seed 时，把它写进 prompt 开头当锚点。
- 缓存 key 用 `gen_seed`，不再用状态摘要。

### 7.4 校验、重生成与兜底

1. **校验**（本地做，不靠模型自觉）：只收 `speaker` / `line` 两个字段；说话人必须在 `speakers` 里；`seen` 没解锁的秘密词命中就判失败；选项文本、Flag 名、数值不许出现；超长按 §7.2 截断。
2. **重生成**：校验不过 → 用 `gen_seed_attempt = hash(gen_seed, attempt)` 再生成一次，**最多 1 次重试**。第二次仍不过，不再试。
3. **兜底**：重试用完、或者超时（建议 8 秒）→ 直接用 beat 表里的 `fallback`（2–3 句占位）。玩家读完照常往下走，**不能因为生成失败卡住**。
4. **只有校验通过的文本进缓存**；失败的那两次不写缓存，避免把坏文本钉死在这个存档上。
5. 读档/回看：只读缓存，不重新生成；缓存丢了（老存档）就按同一个 `gen_seed` 重建，结果仍然一致。

### 7.5 主线为什么不会被带偏

AI 只填"这一段内部的台词"，下一段是剧本写死的 label。它没有能力决定跳哪、拿不拿 Flag、谁出场、结局怎么判——所以走向永远归主线，玩家看到的对话才会变。
